<objective>
Reconcile the three disagreeing hardcoded brand rosters (`src/data/catalog.ts` BRANDS — 20 brands missing
Hettich/Kich; `src/components/catalog/CatalogLibrary.tsx` BRAND_REGISTRY — 22 brands, the most complete;
`src/components/BrandTrustStrip.tsx` LANE_1/LANE_2 — 23 brands including three non-hardware brands) into
one canonical module, and widen the narrow `Product.brand` literal union so it stops constraining the
static fallback array to exactly 6 names.

Per D-26, the canonical roster is **hardware-only**: `BrandTrustStrip.tsx`'s Jaquar/Asian Paints/Philips
entries are excluded from this canonical source of truth (they are removed from the *visible* homepage
strip in a later plan, 09-14, when that file is repointed to consume this module — that repoint is out of
this plan's file ownership). This plan's job is narrower and foundational: make the canonical list exist,
correct, and consumable.

Purpose: every later plan that touches brands (Sanity seeding in 09-08, `BrandDiscovery` in 09-13, the
site-wide de-hardcode in 09-14) reads from this one module instead of re-deriving its own roster, which is
the exact failure mode (Pitfall 1) that produced three disagreeing lists in the first place.

Output: `src/data/brands.ts` (new canonical module), `src/data/catalog.ts` (widened type + re-export),
`src/components/catalog/CatalogLibrary.tsx` (consumes the canonical module instead of its own copy).
</objective>
