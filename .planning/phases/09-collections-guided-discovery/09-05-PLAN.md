src/sanity/lib/slugUniqueness.ts exports:
```
export const RESERVED_SLUGS: readonly string[];   // currently ["spaces"] — Pitfall 5 guard
export interface SlugCandidate { _id: string; slug: string; }
export function findSlugCollision(
  candidateSlug: string,
  candidateId: string | undefined,
  existingDocs: SlugCandidate[]
): SlugCandidate | null;
```
Both `space.ts` and `category.ts` build the async custom validator the same way: check
`RESERVED_SLUGS` first, then fetch `*[_type in ["space","category"] && slug.current == $slug]{ _id,
"slug": slug.current }` via `context.getClient({ apiVersion })` (apiVersion from `@/sanity/env`), strip
any `drafts.` prefix from both the fetched `_id`s and `context.document?._id` before comparing, and pass
the result to `findSlugCollision`.

## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Sanity Studio (editor) -> slug-uniqueness GROQ query | An editor saving a `space` or `category` document triggers a server-side (Studio-context) GROQ fetch scoped to `_type in ["space","category"]`, executed at validation time. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-------------------|
| T-9-05-01 | Tampering | space.ts / category.ts slug validator GROQ query | mitigate | The candidate slug is always passed via the `$slug` fetch-parameter object, never string-interpolated into the GROQ template literal — matches the codebase's existing parameterization convention (`getProductsByCategoryQuery`) and RESEARCH.md's T-9-02 mitigation. |
| T-9-05-02 | Tampering | space.ts / category.ts slug field | mitigate | The reserved-slug guard rejects the literal value `"spaces"` on both schemas, preventing the static-vs-dynamic route-precedence collision documented in RESEARCH.md Pitfall 5. |
| T-9-05-03 | Information Disclosure | slug-uniqueness GROQ fetch | accept | The query returns only `_id`/`slug.current` of documents an authenticated Studio editor already has access to; no end-user-facing or cross-tenant data is exposed. |
| T-9-SC | Tampering (supply chain) | npm/pip/cargo installs | accept | No new package-manager installs in this plan — schema-only TypeScript changes. |
</threat_model>
