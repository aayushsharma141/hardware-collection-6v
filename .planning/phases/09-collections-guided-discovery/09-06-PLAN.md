`settings.whatsappNumber` with the existing `@/lib/config` fallback.

    Export `resolveWhatsAppNumber(settings?: SiteSettings | null): string` returning
    `settings?.whatsappNumber || SHOWROOM_WHATSAPP_NUMBER` — this is the one place in this phase's new

    the same `wa.me` + `encodeURIComponent` idiom `getWhatsAppShortlistLink` already uses, consolidated
    here rather than duplicated.

    Export five section-specific message builders, each returning a plain string (never a URL —
    callers combine the result with `buildWhatsAppLink`):
    - `buildHeroExpertMessage(): string` returning
      `"Hardware Collection — I'd like to speak with a hardware expert about my project."`
      (backs the hero's "Ask a Hardware Expert" primary CTA)
    - `buildProjectRequirementMessage(): string` returning
      `"Hardware Collection — I'd like to send my project requirement for a consultation."`
      (backs "Send Project Requirement")
    - `buildCategoryConsultMessage(categoryName: string, whatsappMessage?: string): string` — returns
      `whatsappMessage` verbatim when it is a non-empty string (the CMS-authored
      `category.whatsappMessage` field takes precedence per D-20), otherwise returns
      `` `Hardware Collection — Discuss your ${categoryName}.` ``
    - `buildEmptyCategoryMessage(categoryName: string): string` returning
      `` `Hardware Collection — Ask about ${categoryName} availability.` `` (D-13 empty-category CTA)
    - `buildSearchZeroResultMessage(query: string): string` returning
      `` `Hardware Collection — I'm looking for ${query}.` `` (search zero-results CTA, D-14)
    Also export `buildBrandConsultMessage(brandName: string): string` returning
    `` `Hardware Collection — I'd like to ask about ${brandName} availability.` `` for symmetry with
    the other builders, in case a brand surface is ever wired to a direct WhatsApp link rather than the
    consultation drawer.

    Never interpolate raw caller-supplied text directly into a URL without passing through
    `encodeURIComponent` — every message flows through `buildWhatsAppLink`'s single
    `encodeURIComponent` call before reaching the URL; the interpolated values above
    (`categoryName`, `query`, `brandName`) are always developer-known strings already fetched from
    Sanity or from the search field's own already-rendered query text, matching RESEARCH.md's
    open-redirect mitigation guidance.
