# Phase 9 — UI Design Contract

> Visual and interaction contract for the `/collections` guided-discovery redesign and the new
> `/collections/[slug]` category route. Generated by gsd-ui-researcher from 09-CONTEXT.md (23 locked
> decisions D-01…D-23), the existing implementation, and the locked NAV/QA specs. Verified by
> gsd-ui-checker. **Revision 1** — addresses checker BLOCKED findings (spacing-scale conformance,
> space-tile destination, CLS aspect-ratio gaps, brand-wall a11y contradiction, motion-bucket
> reconciliation, `category.gallery[]` placement, wording).

**Governing sentence (source brief):** *"Don't make the collection page easier by giving users more
controls. Make it easier by giving them better starting points."*

**This is UX evolution, not rebranding.** Every value below either reuses a class/token already
present in `src/app/globals.css` / `src/lib/motionTokens.ts`, or is a direct extrapolation of the
existing visual language (`hc-serif`, `hc-mono`, `.specimen-tray`, `.threshold-card`,
`brightness-0 invert` brand logos, etc.). Nothing here introduces a new palette, a new typeface, or a
new interaction idiom.

### shadcn Initialization Gate — answered N (no prompt required)

`components.json` was not found (confirmed via filesystem scan). Per the gate, the default action for
a component-library-less React/Next.js project is to ask whether to initialize shadcn. That question
is answered **N** without prompting the user, because the phase's own binding constraints make Y the
wrong call here, not an open question:

  (`.specimen-tray`, `.threshold-card`, `.index-row`, `.rail-button`, `.brass-plate`, `.hc-focus`,

- This is a 7-year-old-in-market showroom's launch-adjacent redesign, not a greenfield build — the
  cost of a new abstraction layer is not repaid within this phase's scope.

**Decision:** `Tool: none`. Registry safety gate: not applicable. All new phase-9 components extend
the existing hand-rolled system.

## Spacing Scale

Reuses the `--spacing-unit-*` custom properties already declared in `globals.css`. No new spacing
tokens are introduced. **Every value used in the Component Contracts below now conforms to this
7-value scale** — the three prior deviations (`gap-3`/`pt-3` in the hero, `gap-5` in the Tier-2 grid)
were rounded to scale-conformant neighbors rather than added as exceptions, since none of them was a
deliberate design choice worth carving out.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps (eyebrow pulse dot, mono ref-code padding) |
| sm | 8px | Compact stacking — badge padding, tag chip padding |
| md | 16px | Default element spacing — card inner padding on Tier-2 grid (`gap-4`), gap between stat-row segments, hero CTA gaps, stat-row border-top padding |
| lg | 24px | Section internal padding; mobile page gutter (`--spacing-margin-mobile`) |
| xl | 32px | Gap between grid tiles (space rail); vertical rhythm between stacked hero elements |
| 2xl | 48px | Space between hero and first content section on mobile |
| 3xl | 64px | Space between major landing-page sections (hero → space rail → index → chapters → Tier-2 → brands) — matches `--spacing-unit-xl` |

**Exceptions (genuinely not spacing tokens — sizing/interaction floors, not layout rhythm):**
- `80px` — desktop outer page margin at ≥1280px (`--spacing-margin-desktop`, already sitewide).
- `44px` — minimum interactive touch target (an interaction-sizing floor, not a layout token; see §10).
- Mobile scroll-snap tile width is expressed as `78–85vw` (a sizing ratio, not a spacing token) so the
  next tile visibly peeks in from the edge as a scroll affordance.
- `gap-[1px]` hairline seams between space tiles / Tier-1 threshold cards (`bg-white/[0.13]` peeking
  through) are a border-rendering technique carried over unmodified from the existing
  `CategoryDiscovery.tsx` pattern, not a content-spacing decision — not part of this scale.

## Typography

Declared from **measured, current usage** in `CollectionsClient.tsx` and `CategoryDiscovery.tsx`, not
invented. Two font families, each single-purpose:

| Role | Size | Family / Weight | Line Height | Tracking |
|------|------|--------|-------------|----------|
| Label / Eyebrow | 10–11px | DM Sans, **600 semibold** | 1 (single line) | 0.18–0.22em, uppercase |
| Body | 13–14px | DM Sans, **300 light** | 1.5 | normal |
| Heading (H2/H3 — section titles, chapter titles, category names) | 28–42px responsive | Cormorant Garamond, **400 regular** | 1 (leading-none) | 0.02–0.03em, uppercase |
| Display (H1 — hero only) | 36 / 72 / 84px (mobile / tablet / desktop) | Cormorant Garamond, **400 regular** | 0.92 | 0.03em, uppercase |

**Weight declaration: 3 total weight values across 2 typefaces, by design.** DM Sans carries exactly 2
functional weights — 300 Light (all body copy/descriptions) and 600 Semibold (all eyebrows/labels/
buttons/active states). Cormorant Garamond carries exactly 1 weight — 400 Regular, used for every
display/heading instance; no bold cut of it appears anywhere in the current codebase, and introducing
one now would be a rebrand, not an evolution. Read per-typeface, this is 2 weights on the workhorse
body face and a single fixed weight on the display face, not an open-ended weight palette.

### Measured WCAG contrast (do not assume the luxury palette passes — verified)

Computed via WCAG relative-luminance formula against the actual hex values in `globals.css`:

| Pair | Ratio | AA normal text (4.5:1) | AA large text / UI (3:1) |
|---|---|---|---|
| Bone `#e8e3d9` on cinema-black `#090909` | **15.57:1** | PASS | PASS |
| Bone `#e8e3d9` on obsidian card `#11100f` | **14.86:1** | PASS | PASS |
| Brass `#c8a96e` on cinema-black `#090909` | **8.87:1** | PASS | PASS |
| Brass `#c8a96e` on obsidian card `#11100f` | **8.47:1** | PASS | PASS |
| Muted grey `#aaa49a` on cinema-black `#090909` | **8.05:1** | PASS | PASS |
| Muted grey `#aaa49a` on graphite frame `#181716` | **7.23:1** | PASS | PASS |
| Near-black text `#090909` on brass button fill `#c8a96e` | **8.87:1** | PASS | PASS |
| Lighter gold `#e5c487` on cinema-black `#090909` | **11.93:1** | PASS | PASS |

**Anti-pattern, flagged explicitly:** Bone `#e8e3d9` (or white) text on a brass `#c8a96e` fill
measures **1.76:1** — a hard FAIL. Every filled brass CTA in this phase (hero primary button, chapter
CTAs, active index states, active brand states) **must** use near-black `#090909` text on the brass
fill, never bone/white. This matches the existing `.brass-plate` / shortlist-selected convention
already in the codebase — the contract is to never deviate from it, not to introduce it.

**Conclusion:** every in-use pair clears AA with wide margin (most clear AAA's 7:1). The palette does
pass, but this is now demonstrated, not assumed, and the one real risk (light text on brass fill) is
named so the executor cannot reintroduce it.

## Component Contracts

### 1. Hero

Retains the existing two-axis masthead composition (`CollectionsClient.tsx` lines 78–114) with three
changes: the description copy loses its hardcoded 6-brand list, the two hero CTAs are added, and the
static status bar becomes a live-count stat row.

**Layout (unchanged rhythm):** `grid-cols-1 lg:grid-cols-12`, left axis `lg:col-span-7` (eyebrow +
display title), right axis `lg:col-span-5` (supporting copy + actions + stat row), `items-end`,
bottom border `border-b border-[#c8a96e]`, top padding `pt-28 sm:pt-32`, bottom padding `pb-7`.

- **Eyebrow:** unchanged — pulse dot (`h-1.5 w-1.5 rounded-full bg-[#c8a96e] animate-pulse`) + "AUTHORIZED DIGITAL SHOWROOM · SAKCHI, JAMSHEDPUR" at Label scale.
- **Title:** unchanged Display scale, "THE COLLECTION," `leading-[0.92]`, uppercase.
- **Supporting copy:** rewritten to be brand-count-agnostic: *"Curated architectural hardware for considered residential and commercial interiors — {N}+ authorized partner brands under one Sakchi roof."* `{N}` is the live brand count (see stat row below), not a hardcoded number, so this sentence and the stat row can never contradict each other.
- **Two actions:** stacked directly under the supporting copy on mobile (full-width, `gap-4`), inline `flex gap-4` on desktop — one shared 16px (`md`) gap value in both layouts. Primary = "Ask a Hardware Expert" (`.brass-plate` fill, `#090909` text on `#c8a96e`). Secondary = "Send Project Requirement" (`.rail-button` outline treatment, bone text, brass underline-on-hover). Exactly one filled button — the visual-hierarchy rule in §9.
- **Live-count stat row:** replaces the static "Product specification wall / Sakchi · Jamshedpur" bar. Border-top `border-white/[0.12] pt-4` (16px, `md`), Label scale, flex row with `justify-between` collapsing to `flex-wrap gap-4` (16px, `md`) on mobile. Segments: `{N} CATEGORIES` · `{M} AUTHORIZED BRANDS` · `SAKCHI · JAMSHEDPUR` (brass, mono, always present as the anchor segment).
  - **Zero-count behavior:** if `N` (published categories) or `M` (published brands) resolves to 0 — e.g. Sanity not yet populated — **omit that specific segment entirely**. Never render "0 CATEGORIES" or "0 AUTHORIZED BRANDS." The row degrades gracefully to whatever subset of segments has a non-zero count, with "SAKCHI · JAMSHEDPUR" always present as the floor. This is the same honesty principle as D-13: a stat that would read as a broken or empty showroom is withheld, not displayed as zero.
  - **"20+ Years" line (F-04/D-09):** not rendered by default. Ships only if Mukesh explicitly confirms the claim before launch — treat as a launch-gate checklist item, not shipped copy. The stat-row layout must not assume its presence (i.e., do not build a fixed 3-slot layout that leaves a visible gap if this line is absent).

### 2. Space-Led Intent Tiles (D-01, D-02, D-22)

Six tiles: `KITCHEN`, `ENTRANCE`, `WARDROBE`, `BATHROOM`, `LIVING / INTERIOR`, `COMMERCIAL`.

**Desktop (≥1024px):** CSS grid, 3 columns × 2 rows, `gap-[1px] bg-white/[0.13]` hairline seams
(matches the existing `CategoryDiscovery.tsx` "Five Thresholds" seam technique). Each tile aspect
ratio `3:4` (portrait, cinematic, fixed via CSS `aspect-ratio` — reserves the box before the image
loads).

**Tablet (768–1023px):** 2 columns × 3 rows, same `aspect-[3/4]` ratio.

**Mobile (<768px, D-22):** native CSS scroll-snap horizontal rail — `overflow-x-auto snap-x
snap-mandatory [-webkit-overflow-scrolling:touch]`, each tile `snap-center`, tile width `78–85vw`
**with height fixed by the same `aspect-[3/4]` ratio as desktop** (not an explicit pixel height) so the
next tile visibly peeks at the edge as a scroll affordance and the browser reserves the correct box
before the image loads — this pins the last of the three previously-unpinned surfaces flagged against
the CLS ≤ 0.10 gate (QA_AND_ASSET_PROTOCOL.md Stage B). No JS carousel, no autoplay.

**Image weighting (70% environment / 20% product / 10% text-interface):**
- The photograph itself carries the 70/20 split as an asset-production instruction (contextual room
  scene with the hardware naturally in-frame, not an isolated product shot) — not a runtime CSS effect.
- The remaining 10% is the text-interface layer: a bottom scrim gradient `linear-gradient(to top,
  rgba(9,9,9,0.92), rgba(9,9,9,0) 55%)` sits under every tile regardless of the photo's own tonal
  values — text legibility must never depend on the specific image (accessibility invariant, not a
  per-image judgment call).
- Content on the scrim, bottom-aligned: tile title (Heading scale, uppercase, e.g. "KITCHEN"), one-line
  description below it (Body scale, muted), an **"Explore {Space Name}"** affordance (e.g., "Explore
  Kitchen," arrow icon + visible label — never a bare "Explore" with no name, and never an unlabeled
  arrow) at the base.

**Hover (desktop, 180ms — card-hover budget):** image `scale(1.04–1.06)`, scrim opacity +8%, arrow
`translateX(+6px)`, tile border brightens to `brass-rule` per the existing `.threshold-card` /
`.specimen-frame` hover pattern. All effects ≤180ms.

**Destination — resolved explicitly (previously undefined for multi-category spaces):**

A space's `linkedCategories[]` (D-11) is an array, so "link to a category" is not always a single,
well-defined target. Resolving this as an anchored/filtered subset of the Collection Index would
quietly reintroduce a filter control under a new name and breach D-18 — so it is resolved as two
distinct, honest cases instead:

- **Single linked category** (`linkedCategories.length === 1`): the tile links directly to
  `/collections/[slug]` for that one category. No intermediate page.
- **Multiple linked categories** (`linkedCategories.length > 1`, the common case — e.g. ENTRANCE
  plausibly links door hardware, locks, and glass hardware): the tile links to a **new, dedicated
  route, `/collections/spaces/[slug]`** (nested under `/collections` to stay inside the spirit of
  D-15's "SEO addressability lives under `/collections`," rather than introducing a bare top-level
  route). This is a genuine content page, not a filtered view: it renders the space's own hero
  (`space.image` + `space.description`) followed by each linked category presented as a full card —
  reusing the **Tier-2 Compact Grid card treatment** (§5) at whatever count `linkedCategories[]`
  actually has (typically 2–4, not the whole catalogue) — each with its own title, one-line
  description and **"Explore {Category Name}"** action to `/collections/[slug]`. The set of categories
  shown is fixed entirely by editor authorship of `linkedCategories[]`, not narrowed by a
  visitor-chosen criterion at runtime, which is what keeps this a landing page rather than a filter.
- **Flag for planner:** `/collections/spaces/[slug]` is not named in D-15/D-16's amended public-routes
  lock ("/" + "/collections" + "/collections/[slug]"). This spec treats it as a necessary consequence
  of D-01/D-02/D-11 — the space-led entry system (the phase's primary discovery mechanism) has no
  functioning destination for any space with more than one linked category without it. Recommend the
  planner either fold this route into the D-16 amendment during planning, or raise it back to the
  owner as a flag in the same register as F-01…F-05. This spec assumes the route ships.

**Keyboard & screen-reader contract (D-22):**
- Rail container: `role="list"` `aria-label="Explore by space"`. Each tile: `role="listitem"` wrapping
  one focusable `<Link>`.
- Tiles remain in normal document tab order regardless of scroll position; focusing an off-screen tile
  natively scrolls it into view (browser default scroll-snap + focus behavior — no custom JS required).
- No content is reachable ONLY via horizontal swipe — every tile's title, description and destination
  are also present in the Collection Index (§3) at the category level, so keyboard users always have a
  non-rail path to the same underlying categories.
- `prefers-reduced-motion`: disable `scroll-behavior: smooth` (fall back to `auto`) and remove the
  hover scale/translate transforms; the scroll-snap **positioning** itself is not decorative motion (it
  is a discrete, user-initiated layout behavior) and remains active under reduced motion.

### 3. Collection Index (D-04)

Full-width editorial list, **not** a sidebar (the old `CollectionFilterRail` was sticky-left; that
affordance is retired with the filter system it served). Every published category, ordered by
`displayOrder`, numbered `01 -` upward, complete list always rendered — no "view all" expander, no
grouping, no pagination.

**Layout at 13+ entries:** responsive CSS columns, not one long list — `columns-1 md:columns-2
lg:columns-3` (or an equivalent grid), so the list reads as a considered reference table rather than a
scroll marathon. `break-inside-avoid` on each row so no row splits across a column break.

**Row anatomy (reuses `.index-row` from the retired filter rail almost verbatim):** number prefix
(brass, `hc-mono`, `01` zero-padded), category name (Label scale, uppercase), optional one-line
eyebrow, chevron/arrow affordance at the row's trailing edge. Row `min-height: 44px`, bottom hairline
`border-white/[0.04]`.

**Hover/focus:** brass underline rule sweep (`.architecture-rule` pattern — `transform: scaleX(0.18)`
resting, `scaleX(1)` on hover/focus, 220ms `var(--standard)` ease — this 220ms is `.architecture-rule`'s
existing sitewide CSS timing, not a NAV-plan S4 bucket applied fresh here; see the motion-bucket
exception in §10) plus text brightening from muted `#aaa49a` to bone `#e8e3d9`.

**Full-row click target:** the entire row is one `<Link>` to `/collections/[slug]` — not a state
setter (D-15/D-18). This is the only place in the redesign explicitly designed for a visitor who
already knows the taxonomy and wants direct access, so it must never itself introduce a filter or
search step.

### 4. Featured Collection Chapters — Tier 1 (D-03)

3–5 CMS-flagged (`category.featured === true`), **hard cap enforced in code** so an editor over-flagging
`featured` cannot degrade the page back into repeated large cards.

**Chapter anatomy:**
- Chapter number: `hc-mono`, brass, e.g. `CHAPTER 01` or `01 / 04`.
- Title: Heading/Display scale (Cormorant, 400, uppercase) — the category name.
- One-line thesis: a single-sentence editorial line pulled from (or authored against) `category.overview`
  — this is the collection's "why," not a features list. Body scale, `#aaa49a`, `max-w` clamp so it
  never wraps past 2 lines.
- Brand line: small-caps brand names carried in this collection, `hc-mono`, e.g. `HÄFELE · DORSET ·
  GODREJ` — sourced from `category.brands[]` references.
- CTA: `Explore {Category Name} →` — text-link weight (not a filled button; see §9's one-filled-button
  rule), brass arrow, `.architecture-rule` hover underline (same pre-existing 220ms primitive and same
  §10 motion-bucket exception as the Collection Index).

**Alternating rhythm (this is the mechanism that prevents the "large card / large card / large card"
repetition the redesign exists to eliminate — source brief S15):**

| Chapter position | Pattern | Treatment |
|---|---|---|
| 1st, 3rd, 5th | **Pattern A — Full-bleed overlay** | Full-bleed cinematic image, aspect `21:9` desktop / `16:9` mobile (already pinned, fixed via CSS `aspect-ratio`), text block overlaid bottom-left on scrim, sits directly on `#090909` |
| 2nd, 4th | **Pattern B — Split frame** | 55/45 image-left / text-right split inside a bordered card (`border border-white/[0.12]`), image column pinned to `aspect-[4/5]` (portrait, appropriate to the narrower 45% column — reserves the box before load, required for the CLS ≤ 0.10 gate), seated on `#11100f` obsidian panel so it visually recedes one step from Pattern A |

Alternation also flips text-block alignment (Pattern A: bottom-aligned overlay; Pattern B:
vertically-centered within its column) so consecutive chapters never share a silhouette. This satisfies
"alternating rhythm" as a structural rule, not a per-chapter design decision the executor has to
reinvent for chapter 3 vs chapter 5 — same position parity, same pattern, always.

**Reveal motion:** 220–250ms per NAV plan S4 (drawer/grid-reveal budget) — opacity + `y: 14→0`,
`AnimatePresence`/`whileInView`, no pinning, no parallax (that visual-tension budget is reserved for the
homepage per `motionTokens.ts` — `/collections` is not chapter 1 of the homepage cinematic sequence).
This bucket is correctly applied here: a chapter's entrance-into-view is a genuine reveal-on-mount, not
a hover state, unlike the CTA underline immediately above it.

### 5. Tier-2 Compact Grid

Remaining published categories not in the Tier-1 cap (and, per §2, reused unmodified as the card
treatment for a space-landing page's linked-category list). Must read as **clearly subordinate** to
Tier-1 without resembling the retired catalogue `ProductCard.tsx` treatment — this tier is for
*categories*, not products, and must not borrow the shortlist-button affordance or `.specimen-tray`
framing that signals "this is a product you can add to a list."

**Layout:** dense grid, `grid-cols-2 md:grid-cols-3 lg:grid-cols-4`, `gap-4` (16px, `md` — revised down
from the previously non-conformant `gap-5`/20px; a tighter gap also better suits this tier's "denser,
more subordinate" register than a looser one would). Thumbnail aspect ratio `4:3` (squarer, smaller
than Tier-1's `21:9`/`16:9`/`4:5`), fixed via CSS `aspect-ratio`.

**Card treatment:** reuse `.threshold-card` (already established in `CategoryDiscovery.tsx` for exactly
this "subordinate but still substantial" register) — 1px hairline border, brass top border appears only
on hover/focus, image opacity `0.8–0.9`, no glow/sweep effects (those are reserved for product specimen
frames). Content: category name at Heading scale but the smaller end of its range (16–20px effective
here, not the 28–42px used for section titles), one short tag line (not a paragraph), and an
**"Explore {Category Name}"** text + arrow affordance — the same canonical action-label pattern used in
§2 and §4, never a bare unlabeled arrow.

**Full click target:** entire card links to `/collections/[slug]`.

### 6. Brand Discovery (D-08)

Two tiers, matching the existing codebase's two already-built brand treatments — reuse both rather
than inventing a third:

**Featured brands (editorial, desktop):** reuse the `InteractiveBrandWall.tsx` typographic-list
pattern — large brand-name typography (`text-5xl lg:text-7xl xl:text-8xl`, DM Sans light), rest-state
dimmed to `rgba(255,255,255,0.35)`, hover brightens the active name to full white and dims siblings to
`0.12`, hover reveals tagline + material/finish detail + "Explore Collection" outline button. Mobile
falls back to the existing simple 2-column text list. Limit this treatment to `brand.featured === true`
brands (the source brief's six-card scale this pattern was built for) — do not force 20+ brands through
this heavy per-item hover choreography. This tier already carries the full title + description + action
triad required by §10.

**Full alphabetical logo wall (20+ brands):** a **static, alphabetically-sorted grid**, not the
`BrandTrustStrip.tsx` auto-scrolling ticker — "alphabetical" implies a scannable reference list for the
"I already know the brand" mental model, which continuous horizontal motion actively works against.
Reuse `BrandTrustStrip`'s exact monochrome logo treatment: `brightness-0 invert` on every raster/SVG
logo (brand kits arrive in a dozen different color systems; forcing monochrome is what keeps the wall
from reading as a rainbow ad-strip against the bone/brass/near-black palette), dimmed rest opacity
`~55–65%`, full-opacity + brass 1px border on hover/focus, and the same wordmark fallback (site's own
DM Sans, uppercase, wide-tracked) for the brands with no supplied logo asset.

- Grid: `grid-cols-3 sm:grid-cols-4 md:grid-cols-6`, each cell pinned to `aspect-[3/2]` (fixed via CSS
  `aspect-ratio` — accommodates both wordmark and monogram logos via `object-contain` without layout
  shift, required for the CLS ≤ 0.10 gate) and bordered per `.threshold-card`/`.specimen-frame` cell
  conventions, sorted `localeCompare` on `brand.name`.

**Accessibility exception for this specific tile type (scoped, not a silent contradiction of §10):** the
logo wall's only visible content per cell is the logo itself — for a recognizable brand mark, the
wordmark **is** the name, unlike a category or space photograph, which never encodes its own
destination visually. Rather than add a redundant visible caption under 20+ already-crowded cells, each
cell instead carries `aria-label="Ask about {Brand} in a consultation"` (and, for desktop mouse users,
`title="{Brand} — Ask about availability"`) so screen-reader and keyboard-only parity is met without
visual clutter. §10's "title + description + action" rule is written to exclude this one tile type on
these grounds — every other card type in this phase (space tile, chapter, Tier-2 card, and the
featured-brand tier above) still carries the full visible triad with no exception.

**Interaction — brand tiles are NOT filter triggers (Claude's Discretion, reasoned call):** D-18
removes query-param brand filtering from `/collections` entirely, and no `/brands/[slug]` route is in
this phase's scope. Rather than resurrect `?brand=` filtering through the back door, each brand
tile/row's action **opens the existing consultation drawer pre-contextualized with that brand** —
reusing `ConsultationContext.brand: { slug, name }` and `intent: "consultation"` (already-shipped
primitive, `src/components/consultation/ConsultationContext.ts`). This continues the showroom-
conversation model (D-19) instead of reintroducing a filtered product list, and requires no new route.
If a future phase finds evidence that visitors need a full brand catalogue page, that is a new decision,
not an assumption baked in here.

### 7. Category Page — `/collections/[slug]` (D-15)

**Section order (top to bottom):**

1. **Breadcrumb:** thin, Label scale, "Collections / {Category Name}" — link back to `/collections`.
2. **Category hero:** `category.heroImage` (D-10, new field) full-bleed, `50–60vh` desktop / `40vh`
   mobile, bottom scrim (`linear-gradient(to top, rgba(9,9,9,0.92), transparent 55%)`, same invariant
   as §2 — legibility never depends on the specific photo). Overlaid bottom-left: eyebrow ("SHOWROOM
   FAMILY · {family}"), title (Display/Heading scale), one-line `category.description`.
3. **Overview panel:** `category.overview` as body copy (longer editorial paragraph than the hero's
   one-liner), `keyFeatures[]` as a short tag/bullet row, `suitableFor[]` as small pill tags
   (Residential / Commercial / Hospitality).
4. **Gallery strip** (new — gives `category.gallery[]` (D-10) its home; previously unreferenced in this
   spec): renders **only if `category.gallery[]` is non-empty**, directly beneath the overview panel. A
   static horizontal row of secondary lifestyle/finish/detail images distinct from the single
   `heroImage` — supplementary texture, not a second hero. Each image pinned to `aspect-[4/3]` (fixed
   via CSS `aspect-ratio`, required for the CLS ≤ 0.10 gate), `object-cover`, no lightbox this phase
   (a click-to-enlarge viewer would be scope creep beyond what D-10 asks for — plain static strip only).
   Alt text: `"{Category Name} — detail {index}"`. If `gallery[]` is empty, this section renders nothing
   (no placeholder frames) and the page proceeds straight from the overview panel to brands carried.
5. **Brands carried:** small logo row for `category.brands[]`, same monochrome treatment as §6, each
   opening the brand-contextualized consultation drawer (not a filter).
6. **Contextual CTA (top instance, low visual weight):** inline text-style CTA sitting within the
   overview flow — "Discuss your {category name}" — driven by `category.whatsappMessage`.
7. **Product grid** (only if `products.length > 0`): retained `ProductCard.tsx` tiles in an editorial
   grid, opening the retained `ProductDetailDrawer` via `?product=<slug>` (NAV plan S3E, unchanged).
8. **Contextual CTA (bottom instance, high visual weight):** full-width bordered panel, same copy as #6
   — page terminus, decisive rather than another shout. This is the §9 "calm invitation not repeated
   banner" pattern: identical copy, escalating visual weight, exactly twice on the page.

**Empty-category variant (D-13 — zero published products; must never look broken):**

- Sections 1–6 above render **unchanged and in full** — `heroImage`, `overview`, `keyFeatures`,
  `suitableFor`, the optional `gallery[]` strip, and `brands` are already substantive content per D-13,
  and rendering them regardless of product count is what keeps this page from ever being a thin stub.
- Section 7 (product grid) is replaced — never with a skeleton loader, ghost grid, "Coming Soon" grid,
  or any fake/placeholder product card (locked project rule: no fake/mock/placeholder products, ever).
  Replaced with one honest content panel, visually weight-matched to what a populated grid would occupy
  (so the page layout doesn't visually collapse into a stub): heading **"See {Category Name} at Our
  Sakchi Showroom,"** body copy per the Copywriting Contract, CTA "Ask about {Category} availability."
  Reuses the existing empty-state panel style already in `CollectionsClient.tsx` (`bg-[#11100f] border
  border-white/[0.12] p-12 text-center`) with the same neutral `Compass` icon (not a warning icon — this
  is an invitation, not an error).
- Section 8 (bottom CTA) still renders — it becomes the primary conversion path on an empty-category
  page, not a redundant afterthought.

### 8. Search (D-14)

One elegant field — not a marketplace search bar, no dropdown filter panel attached to it (that
attachment is exactly what's being removed).

- **Field:** single input, brass icon-left (`Search`, `lucide-react`), height `48px` (unchanged from
  current `CollectionSearchBar`), border `border-white/[0.18]`, focuses to `border-[#c8a96e]` over
  **150ms** (button/filter budget).
- **Placeholder rotation:** cycles every ~4s through example queries — `Try "soft-close hinges"` /
  `Try "matte black handles"` / `Try "Häfele"` — swapped instantly (no cross-fade animation) so
  `prefers-reduced-motion` is satisfied by construction, not by a separate code path. Rotation pauses
  the moment the field has focus or a value.
- **Results presentation:** inline reveal below the field (not a full-page re-render) grouped under two
  Label-scale headers, **"Collections"** and **"Products"** — max 5 rows each, "See all results for
  "{query}"" link if more exist. Matching now runs against `searchKeywords[]` (D-14) in addition to
  name/description, so a customer typing what they'd say in the showroom ("cupboard slides") still
  resolves.
- **Zero-results state:** never a bare "0 results." Heading + body per the Copywriting Contract, plus an
  inline WhatsApp CTA prefilled with the literal search term — turns a dead end into the fourth mental
  model's path ("I don't know what I need" → ask an expert), matching the showroom-salesperson framing.

### 9. Contextual CTAs — Visual Hierarchy (D-20, D-21)

**The one rule that prevents "repeated banners":** at any single scroll position, **exactly one filled
brass CTA button is visible on screen.** Every other conversion prompt on screen at that same moment is
an outline, ghost, or text-link treatment. This is enforced structurally, not left to per-component
judgment:

| CTA | Where it lives | Visual weight |
|---|---|---|
| "Ask a Hardware Expert" | Hero, once | **Filled** (primary) |
| "Send Project Requirement" | Hero, once | Outline (secondary) |
| Per-category "Discuss your {category}" (top) | Category page, inline in overview flow | Text-link |
| Per-category "Discuss your {category}" (bottom) | Category page, page terminus | **Filled**, full-width panel |
| "Need help choosing? Consult a specialist" | Floating capsule, sitewide, appears after scroll > 300px | Ghost/glass capsule — deliberately lower-key than either named CTA, and copy-distinct so it never reads as a duplicate |
| Brand-tile action | Brand discovery | Text-link ("Explore Collection") or none (logo wall tiles open the drawer directly on click, no visible button chrome) |

Because the hero's filled button and a category page's bottom filled button never share a viewport
(they're on different pages, and the hero's is above the fold while any category page's is at the
bottom), the "one filled button on screen" rule holds throughout the whole experience, not just within
a single component.

### 10. Accessibility Contract

- **Contrast:** see the measured table above — every pair in active use clears AA (most clear AAA).
  The one documented anti-pattern (bone-on-brass-fill, 1.76:1) must never occur; every filled brass
  surface uses `#090909` text.
- **Focus states:** every new interactive element (space tiles, index rows, chapter CTAs, brand tiles,
  search field, category-page CTAs) uses the existing global `:focus-visible { outline: 2px solid
  var(--brass); outline-offset: 3px; }` or the `.hc-focus` utility. No new component suppresses
  `focus-visible` without supplying an equivalent replacement ring.
- **Touch targets:** minimum `44×44px` for every discrete control (buttons, close icons, search clear
  button, collection-index rows via `min-height: 44px`). Tiles and cards are always far larger than
  44px and pass trivially — the only components that need explicit floor-checking are compact index
  rows and icon-only buttons.
- **Full-card click areas:** every tile/card/row in this phase (space tile, chapter, Tier-2 grid item,
  index row, brand tile) has its **entire bounding box** as a single click/tap/focus target — one
  `<Link>` or `<button>` wraps the whole card. Unlike `ProductCard.tsx` (which legitimately nests a
  secondary shortlist button inside its card), no Phase 9 discovery card carries a second nested
  interactive element — one card, one action, no focus-order ambiguity.
- **Imagery is never the sole navigation affordance** — every visual card (space tile, chapter, Tier-2
  card, and the featured-brand tier) carries a visible title, a one-line description, and an explicit
  action label ("Explore Kitchen →" / "Discuss your Kitchen") in addition to its image, **with one
  narrow, explicitly scoped exception:** the alphabetical brand logo-wall cells (§6), where the logo
  itself already encodes the brand name and a redundant caption would clutter a 20+-cell grid — those
  cells substitute `aria-label`/`title` text for the missing visible caption so screen-reader and
  keyboard-only parity still holds. No other card type in this phase carries this exception.
- **`prefers-reduced-motion`:** every hover scale/translate/scrim-opacity effect introduced by this
  phase is added to the existing `@media (prefers-reduced-motion: reduce)` block in `globals.css`
  (which already disables `.light-sweep-overlay`, ambient animations, and `.cinema-skew-layer`). Under
  reduced motion: chapter reveals become simple opacity fades (no `y` translate), tile hover scale/
  translate become no-ops, and the mobile scroll-snap rail switches `scroll-behavior: smooth` → `auto`.
  The scroll-snap **positioning** itself is a discrete, user-initiated layout behavior, not decorative
  motion, and stays active under reduced motion.
- **Motion budget (NAV plan S4, binding, do not exceed):** button/filter interactions 150ms; card hover
  180ms; command-bar-style state changes 200ms (not applicable this phase — no command bar ships);
  drawer/grid reveal 220–250ms. Mapped explicitly per component in each section above.
- **`.architecture-rule` timing exception (Collection Index row hover — §3, Chapter CTA hover — §4):**
  this underline-sweep is an already-shipped, sitewide CSS primitive (`globals.css`, hardcoded
  `transition: transform 220ms var(--standard)`), used unmodified everywhere it already appears on the
  site (search-reset link, mobile-row hovers, etc.). Read literally, a hover-state underline belongs in
  NAV plan S4's 150ms (button/filter) or 180ms (card-hover) bucket, not its 220–250ms drawer/grid-reveal
  bucket — this primitive sits roughly 40–70ms outside that expectation. It is being kept exactly as-is
  rather than retimed or forked, because (a) retiming the shared class would shift every other sitewide
  consumer of `.architecture-rule`, not just this phase's new usages — outside this phase's scope — and
  (b) forking a second, phase-local underline class at 180ms would fragment the hover-state visual
  language into two competing speeds on the same page, which is worse than one consistent 220ms. This
  is a named, accepted exception; no new component in this phase should invent a third underline
  timing.
- **Landmarks:** hero as `<header>`; space rail as a `role="list"` region with `aria-label="Explore by
  space"`; collection index as `<nav aria-label="Collection index">`; each chapter as a `<section>`
  with `aria-labelledby` pointing to its own heading id.
- **Keyboard reachability of the mobile scroll-snap rail:** every tile stays in normal tab order
  regardless of scroll offset; every tile's underlying categories are also reachable via the Collection
  Index (§3), so no content is horizontal-swipe-only.
