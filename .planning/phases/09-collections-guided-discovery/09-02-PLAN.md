- D-24 (space-then-category, one route family): `/collections/[slug]` resolves against `space`
  documents first, then `category` documents. RESEARCH.md's Pattern 1 code example and the note that a
  space with only one `linkedCategories[]` entry does not need its own landing page (only spaces with
  >1 linked category get one, per RESEARCH's original architecture note on the now-rejected
  `/collections/spaces/[slug]` route) together define the exact branching this module must encode.
- D-03 (CMS-driven tiering, hard cap 3-5 in code): "Enforce a hard cap of 3-5 featured chapters in code
  so the page cannot degrade back into all-large-cards if editors over-flag `featured`." This module
  enforces the upper bound (5) in code; the lower bound (3) is an editorial/CMS expectation, not a
  code-enforced floor — there is no sane way to synthesize a 3rd chapter from nothing if fewer than 3
  categories are flagged, so this module never pads.
- D-27 (cross-type slug uniqueness, blocking): "both Sanity schemas must validate that a slug is
  unique across BOTH types. A collision silently shadows one document with the other." RESEARCH's
  Pitfall 5 additionally flags the literal slug `"spaces"` as needing a reserved-word guard, since it
  would collide with the (rejected but structurally instructive) `/collections/spaces/[slug]` path
  segment if a category or space were ever named "Spaces" in Studio.
